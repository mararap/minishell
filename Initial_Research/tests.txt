### 2.1 `ms_init_shell`, `ms_free_shell`

### 2.2 Env list

#### `ms_env_get_value`

### 2.3 Loop / line handling

#### `ms_handle_line`

* `line == NULL` → no crash
* `line == ""` → no tokens/exec
* valid command updates `shell.last_exit_status`
* syntax error should not execute anything
* ensure tokens and command lists are freed on all branches (run under valgrind)

`ms_handle_line` is central: it calls lexer → parser → executor and stores status.

#### `ms_main_loop`

* interactive mode: prompt shown, history works
* ctrl-D exits (readline returns NULL) and prints `exit\n` only in interactive
* empty lines don’t get added to history (your code checks `line[0] != '\0'`) 

### 2.4 Signals

#### `ms_setup_interactive_signals`

* ctrl-C: new prompt on new line (your handler writes newline + readline redisplay)
* ctrl-: does nothing (SIGQUIT ignored)

#### `ms_setup_child_signals`

* child should get default SIGINT/SIGQUIT

**Critical runtime test**: while a foreground child runs (e.g. `sleep 5`), ctrl-C should stop the child and return to prompt (bash-like) .

### 2.5 Lexer / parser

#### `ms_lex_line`

Token correctness:

* spaces and tabs separate tokens
* produces tokens for `|`, `<`, `>`, `<<`, `>>`
* quote handling:

  * `'` makes contents literal (no `$` expansion)
  * `"` allows `$` expansion 
* `$VAR` expansion and `$?` expansion

Also test:

* mixed quoting: `ab"cd"ef`, `ab'cd'ef`
* edge: `$` at end, `$` followed by non-identifier

Memory:

* many short concatenations in lexer can leak if intermediate strings aren’t freed; valgrind this hard.

#### `ms_parse_tokens`

Builds command list separated by pipes. On errors, prints specific messages like:

* `minishell: syntax error near '|'` for leading pipe 
* `minishell: syntax error` for redirect without target 

Test:

* leading pipe: `| ls`
* double pipe: `ls || wc` (should error)
* redirect missing target: `echo >`
* pipe at end: `echo |` (should error like bash)

Memory:

* on parse error, ensure allocated `t_command` is freed (valgrind).

#### `ms_free_token_list`, `ms_free_command_list`

* call after lex/parse for:

  * empty list
  * 1 node
  * many nodes
* valgrind confirms no “definitely lost”

## 3) End-to-end application test cases (bash reference)

### How to run each test

For each test script:

1. Run it in bash:

```bash
bash --noprofile --norc < script.txt > bash.out 2> bash.err
echo $? > bash.status
```

2. Run it in minishell:

```bash
./minishell < script.txt > ms.out 2> ms.err
echo $? > ms.status
```

3. Normalize prompt from minishell output (prompt string is `minishell$ `) :

```bash
sed -i 's/minishell\$ //g' ms.out ms.err
```

4. Compare:

```bash
diff -u bash.out ms.out
diff -u bash.err ms.err
diff -u bash.status ms.status
```

> For tests involving `exit`, run that case alone, because it ends the shell early.
